## 2. 落地内容

### 2.1 多维置信度（`security/confidence.py`，自检 19/19）

七个维度加权：规则强度 / 数字签名 / 模型表态 / 接地 / **区分性证据** / 历史一致性 / 注入洁净。

**关键设计：三条硬门槛一票否决**（对应材料里"神经符号护栏"——不把裁量权交给加权分数）：

| 门槛 | 理由 |
|---|---|
| 无**区分性证据** | 本项目实测：无区分性证据的攻击判定占 62–71%，这正是误报主因。调权重拦不住——那种回答规则分满分、接地通过，加权分反而高达 0.713 |
| 接地校验未通过 | 回答里有编造 |
| 结论自相矛盾 | 同一结论段既说攻击又说良性 |

⚠ **刻意不把「标记注入」当门槛**：实测该标记误标率 **52.7%**（提示词加固 H4 的副作用），
拿它当一票否决会把几乎所有告警推进人工，使自动定性形同虚设。它只作降权维度。

路由三档：`auto_attack`（弹通知）/ `review`（只记录 + 需复核）/ `auto_benign`（静默留档）。

### 2.2 数据驱动良性基线（同模块）

* 键 = `(进程, 目的端口, 协议)`，**不含远端 IP**——IP 会漂移（CDN/云/轮换），
  「哪个程序连哪个端口」才是稳定指纹；把 IP 放进去基线永远学不到东西。
* 升格条件：**≥8 次且从未判为攻击**；30 天不出现则掉出（防陈旧白名单）。
* 命中则降权到 ≤12 分（低于阈值，不再弹通知），但**保留记录**可审计。
* ⚠ 学习必须看到**全部**发现（不论是否超阈值）：否则被基线压到阈值以下的模式永远学不到，
  基线就永远建立不起来。
* ⚠ 有已知边界：**长期低频、行为一致的攻击者符合「正常」形状**（慢速渗透），
  所以它只做降权，不删除记录。

### 2.3 RAG 良性判据（`tools/add_benign_seeds.py`）

原来 26 条种子**全是攻击判据** —— 检索只告诉模型"怎么算攻击"，
拿不到"这些看起来像攻击的其实是正常业务"的反证知识，**这是误报的直接成因**。

新增 10 条 `kind=benign_pattern`：安装器自解压到 Temp、浏览器 UDP DNS 突发、
开发工具非标端口、厂商固定心跳、Windows 更新/CDN、VPN 周期重协商、定长媒体流、
抗量子握手长度、备份/护盘窗口、以及一条「区分性证据 vs 反面清单」。

⚠ 其中两条（心跳、抗量子长度）**初版过宽**，会把隐蔽攻击也一并豁免 —— 已收紧为
**必须四项条件同时成立**（标准端口 + 可核验域名/证书 + 已签名正规进程）才适用。

### 2.4 H5 思维链（`agent/agent.py`）

要求模型在结论前写出：① 两侧事实（支持正常业务 / 支持攻击，都必须写具体可核验事实）
② 一行 `取舍：…` ③ `置信度: 高/中/低` 自评。

## 3. 三组实测（240 条，同一模型，贪心解码）

| 指标 | C 加固+k3 | D 良性优先 | **E 双向权衡** |
|---|---|---|---|
| Accuracy | 0.713 | 0.621 | **0.742** |
| F1 | 0.785 | 0.664 | **0.795** |
| Precision | 0.931 | 0.989 | **0.984** |
| Recall | 0.678 | 0.500 | 0.667 |
| 严格识别率 | 0.678 | 0.500 | 0.667 |
| **normal 误报率** | 0.150 | 0.017 | **0.033** |
| normal 良性率 | 0.817 | 0.983 | 0.967 |
| conventional 识别率 | 0.924 | 0.742 | **0.924** |
| stealthy 识别率 | 0.750 | 0.533 | **0.767** |
| ai_attack 识别率 | 0.296 | 0.167 | 0.241 |
| **有区分性证据率** | 0.374 | 0.385 | **0.721** |
| 每案 token | 2557 | 2903 | 3211 |

**结论：E 是严格更优的操作点** —— 误报率 **0.150 → 0.033（↓78%）**，
同时 Accuracy / F1 / Precision 全部上升，Recall 基本持平（0.678 → 0.667），
**区分性证据率翻倍（0.374 → 0.721）**——即模型不再靠"量级/时段"下结论，
而是被迫给出可核验的事实。

### 3.1 中途的一个错误实现（必须记录）

D 组把 H5 写成了「**良性解释优先**」——这是对思维链方法的**错误实现**：
思维链应当提升准确率，而不是给一个偏向良性的先验。后果是
**召回掉 0.178**，且损失在三类攻击上**均匀出现**（conventional −0.18 / stealthy −0.22 /
ai_attack −0.13）——均匀分布说明不是"良性种子放过了某些攻击形状"，
而是全局性的保守偏向。

改为**双向权衡**（E）后，召回恢复，误报仍比 C 低 78%。
**教训：安全方向的强制条款必须对称，不能只约束一个方向。**

### 4.3 签名降级有两个部分，少一半就等于没修

第一部分的降级（40 → 10 分）容易被看懂，但**第二部分更隐蔽**：

`analyse()` 有一条「组合加成」规则：命中多条规则时给额外分。而降级时我们把
`signed_valid` 当作**注解**写进了 `finding.rules`。组合加成**不区分注解与真实命中**，
于是它把刚降到 10 分的 finding 又当成"命中了两条规则"加成回去 —— **10 → 25 分**，
加上其他命中仍然越阈值。这类 bug 的症状是"改了分值但告警没少"。

修法是显式声明注解集合，算组合加成时排除它：

```python
_ANNOTATION_RULES = {"signed_valid", "benign_baseline"}
real_rules = [r for r in f.rules if r not in _ANNOTATION_RULES]
```

教训：**注解和规则命中在数据结构上混用，早晚会被别处的"规则数量"逻辑误用。**
自检里为此加了 4 条用例（有效签名→10 分且带注解；无签名→仍 40 分且无注解；
不传 `sig_fn`→行为不变；`sig_fn` 抛异常→不崩且不降级）。

另外两条生产调用路径（轮询路径的 `analyse(...)`、进程事件路径的
`suspect_proc_finding(...)`）**都必须传** `sig_fn`，只改一条等于没改。

### 4.4 上线状态

| 项 | 值 |
|---|---|
| 修复落地时间 | `net_sensor.py` 改于 2026-10-04 13:54 |
| **实际生效时间** | **2026-10-05 19:06:32**（此前进程启动于 10-03 14:33，跑的是修复前的代码） |
| 生效方式 | `Stop-ScheduledTask BlueTeamNetSensor` → 结束残留进程 → `Start-ScheduledTask` |
| 运行身份 | 计划任务 `BlueTeamNetSensor`，AtLogOn、`IgnoreNew`、失败重启 3 次/5 分钟 |

**教训：改完代码不等于修好问题。** 常驻进程必须重启才算上线，
否则评测数字很好看、线上行为一点没变。判断依据很简单：
**进程启动时间要晚于源文件修改时间。**

一个容易误判的现象：`Get-CimInstance Win32_Process` 会看到**两个** `pythonw.exe`
在跑同一个 `net_sensor.py`，看着像重复实例。实际是 `.venv\Scripts\pythonw.exe`
是 **uv 的转发器**（257 KB；真解释器 101 KB；`pyvenv.cfg` 里 `uv = 0.11.5`），
它把基础解释器作为子进程拉起，父子的命令行完全相同。
**判定方法：看日志心跳的时间戳是否成对重复**——只有一个实例会写心跳。

## 5. 诚实边界

1. **E 组的 ai_attack 识别率仍低于 C（0.241 vs 0.296）**：注入类用例上，
   双向推理要求"攻击侧事实"时，模型仍倾向把注意力放在注入本身而非被包裹的行为。
2. **token 成本 +25%**（2557 → 3211/案）：思维链与更多检索上下文是有代价的。
3. **良性基线可被慢速渗透绕过**（见 §2.2）。
4. **良性种子是"附加条件式豁免"**：条件写对了能降误报，写宽了会把攻击一起放过（D 组实证）。
5. 所有数字来自**单一模型（Qwen2.5-3B Q4）+ 单次运行 + 240 条**；
   `variant_agreement` 约 0.75，**有效样本量低于名义 n**，类别级小差异不应作为结论。
6. **注意力熵、LoRA 微调、大小模型级联三项未实施**，其中 LoRA 是明确的后续方向
   （材料里 OpenSOC 用 450 条样本即把准确率从 0% 提到 68%）。
